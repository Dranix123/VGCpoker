# VGC 自动对局测试

## 网页入口

开通的账号可从 VGC「设置 → 自动对局」启动或停止测试、查看最近任务和下载 JSONL 日志。每个账号保存自己的 DeepSeek API Key，并可逐任务选择 Flash 或 Pro、是否启用思考。密钥存于游戏服务内存，重启后需要重新填写。测试记录按账号保存在 `data/playtests/`。

服务器操作员可对已注册账号开通或撤销权限。权限绑定账号 ID，修改昵称不会转移权限。

```sh
python3 server.py grant-playtest Dranix J4DE_Fieldlark
python3 server.py revoke-playtest 某个账号
```

## 独立接口

独立服务默认监听 `127.0.0.1:4144`。它直接调用斗地主、4A4 和传送带的规则程序，无需账号、房间、浏览器或真人操作。每个测试座位各自决策。同一个 DeepSeek 密钥可以服务全桌，每次调用只给模型当前身份的手牌、公共牌面和候选动作。开局保留、技能结算等没有枚举完所有可选动作的步骤由规则 AI 执行。

## 启动

在 macOS 的 zsh 里运行。密钥通过终端提示输入，输入时不会显示。

```zsh
cd "/Volumes/PortableSSD/webpages/poker"
read -rs 'DEEPSEEK_API_KEY?DeepSeek API Key: '
printf '\n'
export DEEPSEEK_API_KEY
python3 playtest.py
```

默认模型为 `deepseek-flash`，可在启动前设置 `DEEPSEEK_MODEL`。只跑规则 AI 时，可以直接执行 `python3 playtest.py`。本接口不读取 VGC 网站里的模型配置。 [DeepSeek 模型与接入说明](https://api-docs.deepseek.com/en/)

## 启动测试

以下命令用 DeepSeek 测试两局传送带，从 1 号到 4 号依次使用重铸·丰收、如影随形、烙印和追击之力。指定技能需要的 DLC 会自动启用。指定 `null` 可让对应座位随机选择技能，也可重复指定同一技能。

```sh
curl -sS http://127.0.0.1:4144/runs \
  -H 'Content-Type: application/json' \
  -d '{
    "mode": "conveyor",
    "driver": "deepseek",
    "games": 2,
    "skills": ["重铸·丰收", "twins", "烙印", "chase_force"],
    "options": {"firstOutEndsRound": true},
    "maxSteps": 600,
    "maxModelCalls": 200
  }'
```

| 参数 | 用法 |
| --- | --- |
| `mode` | `landlord` 斗地主，`basic` 4A4，`standard` 4A4A4，`trio` 4A4A4 三人版，`conveyor` 传送带 |
| `driver` | `deepseek` 让模型处理有多种候选的行动，`rules` 全程用规则 AI |
| `games` | 连续测试局数，默认 1。玩法支持跨局等级时按规则继承 |
| `skills` | 仅传送带使用，按座位排列四项，可以填中文名称、技能编号或 `null` |
| `options` | 模式开关，例如传送带的 `firstOutEndsRound`、4A4A4 的 `tribute`。用 `GET /options` 查看可选项 |
| `maxSteps` | 每局最多执行的行动数，默认 600。达到上限的牌局记录为 `step_limit` |
| `maxModelCalls` | 整个任务最多请求多少次 DeepSeek，默认 250。达到上限后由规则 AI 完成余下牌局 |

启动后返回任务 ID。一次运行一个任务，当前任务运行时提交另一个任务会返回 409。

## 查看任务与日志

已开通权限的账号可在「设置 → 自动对局」选择自己的任务，再点任意一局旁边的「回放」。回放沿用观战牌桌，支持播放、暂停、前后单步和拖动进度。旧任务从现有日志还原。

```sh
curl -sS http://127.0.0.1:4144/options
curl -sS http://127.0.0.1:4144/runs/任务ID
curl -sS http://127.0.0.1:4144/runs/任务ID/log
```

每个任务默认写入 `output/playtests/任务ID/`，可用 `--output` 指定其他目录。

- `summary.json` 记录进度、各局赢家和等级、模型请求次数、回退次数及 API 返回的 token 用量。结果中的座位下标从 0 开始，0 对应 1 号玩家。
- `events.jsonl` 逐行动记录座位、候选动作、模型选择及延迟、前后手牌和牌堆状态、规则播报，以及被拒绝的行动。它包含测试牌局各座位的手牌，适合赛后分析。
- `replays/局号.jsonl` 按局独立保存观战画面，同名 `.idx` 用于定位单步。
- API 请求失败或选择被规则引擎拒绝时，日志会记录原因并尝试规则 AI 的行动。如果规则 AI 本身无法继续，任务标为 `failed`，以便定位卡局。密钥和 API 请求头不写入日志。
