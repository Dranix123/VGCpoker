# 纸间 · Paper Club

素描纸张风格的扑克牌网页游戏。Python 3.9+ 标准库服务端、SQLite 数据库、原生 JavaScript 前端，无需安装 npm 或 Python 依赖。

## 启动

```sh
./start.sh
```

浏览器打开 **http://localhost:4141**。默认仅监听 `127.0.0.1:4141`，适合 Cloudflare Tunnel 的本机源站。自定义监听地址或端口：`HOST=0.0.0.0 PORT=4141 ./start.sh`。

Cloudflare 的 Public hostname / Tunnel ingress 中，将域名指向 **http://localhost:4141** 即可。本项目同一端口同时提供网页和 API，不需要单独配置 WebSocket；客户端按约 850ms 同步牌桌状态。域名与 Tunnel 由你手动配置，未更改本机 Cloudflare 设置。

## 功能

- 游戏主菜单：创建房间、单人模式、设置；进入模式后选择玩法及 AI 类型，单人模式自动补齐 AI 并开局。
- 设置统一管理模型 API、玩家昵称与密码，修改密码撤销其他设备会话。
- 注册、登录、退出；随机盐与 PBKDF2-SHA256（600,000 轮）保存密码摘要，HttpOnly / SameSite 会话 Cookie；通过 HTTPS 登录时设置 Secure。
- 六位房间号创建与加入；只有注册玩家可以加入，房主控制开局、AI 席位与连续对局。创建时可选择邀请 AI 的人数与类型；准备室点击空座位也可邀请规则 AI 或模型 AI。
- 服务端判定合法牌型、回合、牌权、身份与胜负。玩家只能读取自己的手牌，其他玩家仅公开剩余张数、升变与亮牌信息。
- 刷新或重新登录后返回现有房间。离线玩家保持席位，对局中任何玩家可认输结束整局。
- 规则 AI 会估算剩余手牌的出牌手数、保留顺子/对子/炸弹，优先够用的跟牌，同队安全领先时让牌，对手临近出完时加强压制；急牌根据自身手牌、队伍与公开牌数选择赠牌和目标。决策不读取对方手牌点数。提供合法出牌提示。模型 AI 支持兼容 Chat Completions 的 HTTPS API，在设置里提供基础地址、模型 ID 与 API Key；模型从合法动作列表中选动作，无效输出或请求失败使用规则 AI。
- 账号积分、六档段位、排行榜、最近 20 场真人战绩。仅整桌真人的对局计分；含任何 AI 的房间全部玩家均不计分。SQL 结算事件防止重复计分。
- 简洁素描游戏界面，桌面与手机手牌自动换行，无需横向滑动。每人只展示自己的最近一手，整桌最新一手正常亮度，之前的略暗；相同花色点数的重复牌显示数量。
- 急牌赠送弹出目标玩家选择，公开显示赠送牌，赠牌后继续正常出牌。
- 桌面与手机响应式大厅、准备室与牌桌；选牌、普通与特殊出法、混子自动/逐张指定、急牌赠牌、协商撤回、猜拳、开局升变。

## 玩法

| 玩法 | 人数 | 牌数 | 胜负与规则 |
| --- | --- | --- | --- |
| 斗地主 | 3 | 54 | 叫分地主，任一农民出完即农民队胜 |
| 4A4A4 标准 2.4 | 4 | 110 | 对座组队；含勾、叉、点、压、死压、回、黑桃 A、升变、急牌和爆牌 |
| 4A4A4 三人 | 3 | 86 | 独立争先，保留标准特殊规则 |
| 4A4 基础 | 4 | 54 | 对座组队，三张起炸，勾叉与基础 4A4 |
| 标准 + Fieldlark DLC | 4 | 150 | 添加额外 40 张牌，包括 Delta 花色 |

房间可选择「回进阶版」「死压进阶版」；停用的“分”玩法不启用。

### 本实现对规则细节的约定

正常出牌及斗地主叫分按逆时针轮转（自己 → 右侧 → 对座 → 左侧），跳过已完成玩家；三人局为自己 → 右侧 → 左侧。特殊截牌和直接获得牌权按各自规则处理。四人局中，已出完者的最后一手无人能管时，自由牌权交给其仍在场的对家。每座展示本轮或上一轮的出牌；不出替换为「不出」，已出完者的牌在下一轮清除。AI 按 1号、2号、3号命名。

1. 用户已确认：四人按对座组队，队分从 3、4、5…K、A、2 循环映射下一局主牌。初始队分为 0、主牌为 3。
2. 四人局仅剩一对对家时直接结算，展示所有玩家剩余手牌。四人队伍第二位成员先出完则该队胜。每队加上自身全员完成时仍在场的人数；下一局主牌取首位完成者所在队的累计分。三人独立计胜局，首位完成者胜，按其累计胜局循环决定下一局主牌。
3. 4A4 基础版与标准版均先亮黑桃 3 定先手；无人亮牌时随机选择先手。多人亮牌时隐藏选择猜拳；平局重猜，有多名胜者时胜者继续猜拳。后续对局首位完成者先发、先出，同时仍有升变确认阶段。
4. 主牌不进入顺子、连对、飞机。用户已确认黑桃 A 允许作为普通 A 单出；作为混子只能在多张组合内使用，不能代替王；代急牌时选牌点击出牌，自动进入赠送目标选择，不能在普通组合中混入急牌。自动配牌枚举常见合法目标牌型；任意独立替代可以逐张指定。
5. 「回」要求当前与响应组合全部同一花色；进阶版要求同牌型、同张数。「回」后的普通牌仍按原基础牌型比较。本轮结束后才重置回的使用次数。
6. 死压进阶版四张牌必须与被死压的点数相同；可在死压者再次出牌前截获牌权。「压」、点 2/主、死压获得自由出牌机会。死压可优先于点截牌，压可以拦截点 2/主后的直接牌权。
7. 急牌在自己的出牌回合使用，消耗自己并赠送一张非急牌，公开显示赠送牌的花色与点数；不占出牌次数，可连续使用急牌并继续正常出牌；用完手牌则转到下一位。只剩急牌自动排末名，多位这种玩家按触发顺序排在实际出完者之后。
8. 叉、勾、点、压、死压有优先响应机会，单人悬浮提示持续显示并自动标记可管的手牌，可改选合法普通牌跟牌，点不出放弃；仅跨回合优先管牌暂停等待，已顺次轮到真人时不暂停；多人同样提示并标记，保持正常轮转，尚无人后续出牌时直接出，有一人出牌时点出牌自动请求其收回，已有两名玩家出牌则失去旧手的优先协商机会。叉后只能用同点单牌勾；无人勾则叉牌者继续自由出牌。勾不可再管，勾牌者直接自由出牌。上家已出完时可抢先特殊出牌；原下一家刚出牌可申请协商，当前已完成两人时不能协商。协商锁住牌桌，同意后恢复上一手之前的状态，再执行请求者的特殊出牌。
9. 斗地主全部不叫时最后一位成为 1 分地主；不使用倍数、春天等额外积分项。真人斗地主每位胜方 +24、负方 −24；其他玩法 +20/−20，积分最低为 0。认输让所在队判负，三人模式其余玩家胜。
10. 王炸可由任意两张/三张/四张王牌组成。DLC 中超过十张的同点炸弹按张数继续增加，仍低于 4A4A4。

完整出牌规则也可在游戏内「玩法手册」阅读。

## 数据与运行

SQLite 文件：`data/poker.sqlite3`，自动创建，包含账号、会话、对局结果和积分事件。数据库与 API 密钥不会纳入 Git。备份可使用 SQLite backup API，避免只复制正在写入的数据库主文件。

房间和正在进行的手牌存储在服务器内存；**服务重启会结束未完成的房间**，账号、积分与已完成战绩仍保留。模型 API 密钥保存在当前账号与房间的服务器内存中，清除配置或服务重启后清除。设置中的 API 配置自动用于你创建的房间；不会返回密钥给浏览器。模型调用只发送该 AI 自己的手牌和公开局面，不发送其他玩家的手牌。

适用于本机持续运行并通过 Cloudflare Tunnel 暴露的单进程部署。不要同时启动多个实例共享实时房间；可以在系统进程管理器中启动 `start.sh` 并配置自动重启。

## 验证

```sh
python3 -m unittest discover -s tests -v
node --check public/app.js
```

测试覆盖牌组与牌型、特殊出牌与截牌协商、主牌与队分、整局 AI 游戏、HTTP 注册与房间权限、账号修改与会话撤销、API 设置与密钥隔离、手牌隔离、真人积分幂等、AI 不计分以及模型动作校验。HTTP 测试使用临时 SQLite 数据库，不写入真实账号数据。模型接口通过模拟返回值验证；真实提供商需要自己的 API Key。

## 文件

- `server.py`：HTTP、账号与数据库、房间、结算、AI 调度与模型接口。
- `engine.py`：牌组、牌型、完整游戏状态与规则 AI。
- `public/`：网页界面、纸张与扑克牌样式。
- `tests/`：规则与 HTTP 集成测试。

出牌操作只需选牌并点击「出牌」，服务端根据当前牌面自动识别普通牌、勾、叉、点、压、死压及进阶；普通跟牌合法时优先普通出牌，否则尝试「回」。急牌自动进入赠送目标选择，已有一人后续出牌时自动发起协商，无单独协商入口。

4A4 基础版不允许任何带牌组合。4A4A4 标准版及三人版中，N 张同点牌（N ≥ 3）可带 1～N−2 个单位，单位统一为单牌或对子，不可混搭；附件点数互不相同，且不同于主组点数。相同主组张数、单位数和单位类型才可正常比大小。斗地主保持经典规则。其他在场玩家都不出后，牌权持有者可重新自由领出合法牌型；已出完者的牌权交给其仍在场的对家。
